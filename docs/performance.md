# 프레임 처리 성능 분석

2026-10-30, `a498b40` 기준으로 Godot 4.7.2와 Apple M4에서 측정했습니다.

## 원인과 변경

- `PlushieHUD._process()`는 매 프레임 다음 공의 `tier`를 할당합니다.
  기존 `BallIcon` setter는 같은 값에도 `queue_redraw()`를 호출해 공의
  무늬·클리핑 계산을 반복했습니다. 같은 값은 건너뛰고, 하이라이트가
  움직이는 동안에만 아이콘의 `_process()`를 켭니다. 크기·종류·흐림·회전
  변경과 하이라이트의 마지막 프레임은 계속 다시 그립니다.
- `Feedback`은 효과가 없어도 매 프레임 빈 배열 두 개를 `filter()`하고
  다시 그렸습니다. 빈 상태는 건너뛰고, 활성 효과는 역순으로 만료 항목을
  제거해 배열을 유지합니다. `clear()`와 모션 줄이기 설정의 외부 파티클
  삭제는 명시적으로 다시 그려 이전 그림을 지웁니다.
- `LocalMatch`는 물리 틱마다 승패를 확인하려고 양쪽 보드의 전체 공 목록을
  직렬화했습니다. 필요한 점수·결과만 authority에서 직접 읽고, 전체 보드
  스냅샷은 기존 20Hz와 시작·종료 전환에만 만듭니다. 전송되는 상태의 깊은
  복사, 물리 계산, 타이머와 승패 규칙은 유지합니다.

Godot는 `_draw()`의 명령을 캐시하므로 상태가 같을 때 다시 그리기를 생략할
수 있습니다. 동작 근거는 [공식 custom drawing 문서](https://docs.godotengine.org/en/stable/tutorials/2d/custom_drawing_in_2d.html#updating)를 참고하세요.

## 변경 전후 측정

동일한 `tools/benchmark_frame_work.gd`를 기준 커밋과 변경 코드에서
실행했습니다. 렌더링 작업량은 초기 4프레임 이후 60프레임 동안 실제
CanvasItem `draw` 신호를 셉니다. CPU 구간은 보드마다 80개 공을 만들고
물리를 고정한 뒤, 60틱 준비 후 `LocalMatch._physics_process(1/60)`를
600회씩 7번 호출한 시간의 중앙값입니다. 스냅샷 생성과 깊은 복사를
포함하며, 준비·물리 시뮬레이션·브라우저·GPU 시간은 포함하지 않습니다.

| 항목 | 변경 전 | 변경 후 |
|---|---:|---:|
| 같은 다음 공 아이콘의 다시 그리기 / 60프레임 | 60 | 0 |
| 빈 이펙트의 다시 그리기 / 60프레임 | 60 | 0 |
| 두 보드의 직렬화 / 600틱 | 1,600 | 400 |
| 해당 600틱의 CPU 시간 중앙값 | 171.096ms | 54.306ms |

보드 직렬화 호출은 75%, 측정한 CPU 구간은 약 68% 줄었습니다.
CPU 표본(ms)은 다음과 같습니다.

- 변경 전: 169.332, 170.099, 170.930, 171.096, 172.039, 172.294, 177.447
- 변경 후: 53.662, 54.256, 54.278, 54.306, 54.392, 55.441, 55.629

이는 특정 처리 구간의 비교입니다. 게임 전체 FPS, 모바일 배터리 사용량이나
WASM 성능 향상률을 의미하지 않습니다. 회귀 검사는 시간 임계값 대신
작업 횟수와 동작을 확인해 실행 환경의 속도 차이에 영향을 받지 않습니다.

## 재현과 검증

```sh
GODOT_BIN=/path/to/godot npm run verify
GODOT_BIN=/path/to/godot npm run build
/path/to/godot --headless --audio-driver Dummy --fixed-fps 60 --path . \
  --script tools/benchmark_frame_work.gd
```

기준 커밋의 별도 worktree에 같은 벤치마크 파일을 복사한 뒤
`godot --headless --editor --path . --quit`로 리소스를 가져오고 같은 명령을
실행하면 비교할 수 있습니다.

`npm run verify`에 `test_frame_work.gd`와 `test_match_frame_work.gd`를
추가했습니다. 아이콘 무효화·하이라이트 종료, 입자·팝업 이동과 만료,
일시정지·삭제·모션 줄이기, 20Hz 전송·스냅샷 분리, 최신 점수에 따른
양쪽 승리·무승부·overflow와 실제 투하·독립된 물리 공간·재경기·정리를
검사합니다. 기존 규칙·한국어/영어·연속 재시작·웹 셸 검사도 함께 실행합니다.

완료한 검증은 다음과 같습니다.

- `npm run verify`: 리소스 가져오기와 생성된 셸 일치 검사를 포함한 15개
  단계 통과. 새 두 테스트의 40개 assertion 모두 통과.
- `npm run build`: release Web export와 해시 경로 후처리 통과.
- Chromium 실제 Web 빌드: 1280×900에서 시작·6회 투하·일시정지·2인 모드
  진입·카운트다운·양쪽 이동과 투하를 확인했습니다. 390×844 모바일
  에뮬레이션에서 한국어 시작 화면·터치 투하·복귀 링크를 확인했고,
  JavaScript/브라우저 console 오류는 없었습니다. 스크린샷도 직접 검토했습니다.
- 별도 코드 리뷰에서 발견한 모션 줄이기 전환의 캐시 무효화 문제를
  재현 테스트로 수정하고 재검토했습니다.

브라우저 확인은 동작·화면에 대한 smoke test이며 FPS나 실제 모바일
기기 성능 측정은 포함하지 않습니다.

## 후속 측정 후보

해변 배경은 움직이는 구름·파도와 고정 장식을 함께 다시 그리고,
`BoardView`는 2인 모드에서 보간된 공과 카트를 함께 다시 그립니다.
정적 부분의 노드 분리나 무늬 기하 캐시는 다음 후보입니다. 이번 변경에서는
화면 구성과 애니메이션 빈도를 유지했으며, 이 후보들의 이득은 별도
브라우저 프로파일링으로 확인해야 합니다.
